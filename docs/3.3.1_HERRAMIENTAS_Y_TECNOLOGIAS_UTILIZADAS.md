# 3.3. DESARROLLO E IMPLEMENTACIÓN

La fase de desarrollo e implementación en el ciclo de vida del software constituye la transición formal desde los modelos conceptuales y artefactos de diseño detallado hacia código fuente ejecutable, probado y desplegable. En el marco del presente proyecto, denominado **FashionStore SaaS Multitenant**, esta etapa se rige rigurosamente por los principios de la metodología **ICONIX Process** (Rosenberg & Stephens, 2007), la cual establece una trazabilidad directa, sistemática y sin fisuras entre los casos de uso, los diagramas de robustez (análisis preliminar de arquitectura), los diagramas de secuencia (diseño detallado) y las unidades de código que componen la solución tecnológica final.

A diferencia de los enfoques tradicionales de desarrollo en cascada con alta carga burocrática, o de los métodos ágiles extremos que prescinden de una fase de diseño arquitectónico formal, ICONIX propone un proceso ágil dirigido por casos de uso (*use-case driven*) centrado en la tríada de modelado de objetos propuesta por Ivar Jacobson: objetos límite (*Boundary Objects*), objetos de control (*Control Objects*) y objetos de entidad (*Entity Objects*). En este contexto, la selección de herramientas, lenguajes de programación, sistemas gestores de bases de datos, bibliotecas y entornos de ejecución no responde a preferencias arbitrarias o modas tecnológicas coyunturales, sino a los requisitos funcionales y no funcionales explícitos emanados del análisis arquitectónico (Bass et al., 2021; Sommerville, 2011).

### 3.3.1.1. Fundamentación Metodológica según el Proceso ICONIX

De acuerdo con Rosenberg y Stephens (2007), el Proceso ICONIX se estructura para evitar tanto el análisis parálisis como la codificación desordenada mediante cuatro hitos fundamentales:
1. **Modelado de Requisitos y del Dominio:** Identificación de casos de uso y sustantivos clave del negocio.
2. **Análisis de Robustez:** Vinculación de los casos de uso con el modelo de dominio mediante tres tipos de estereotipos de análisis (Jacobson et al., 1992):
   - *Objetos Límite (Boundary Objects):* Componentes visuales, pantallas, modales, formularios y puntos de entrada interactivos mediante los cuales los actores externos (cajeros, administradores, clientes) dialogan con el sistema.
   - *Objetos de Control (Control Objects):* Encapsulan la lógica de aplicación, la orquestación de casos de uso, las reglas de negocio, las validaciones transaccionales, las tareas programadas y los servicios de cálculo o inferencia de inteligencia artificial.
   - *Objetos de Entidad (Entity Objects):* Modelan los datos persistentes de larga duración (tablas relacionales, colecciones indexadas, registros contables e información de membresías).
3. **Diseño Preliminar y Detallado:** Asignación formal de responsabilidades a clases de diseño mediante diagramas de secuencia e identificación de signaturas de métodos.
4. **Implementación y Pruebas Unitarias:** Construcción del código fuente y verificación sistemática de invariantes mediante pruebas automatizadas.

A continuación, se detalla la justificación técnica de cada una de las tecnologías empleadas, clasificadas rigurosamente según su rol estereotípico en la arquitectura del sistema.

### 3.3.1.2. Entornos de Ejecución y Lenguajes Base

#### TypeScript 5.x / 6.x (Microsoft Corporation)
- **Rol en el Sistema:** Lenguaje de desarrollo transversal para la totalidad de la plataforma web cliente, la aplicación móvil nativa y el backend transaccional NestJS.
- **Justificación y Razones de Elección:**  
  En un sistema empresarial de retail omnicanal que administra transacciones financieras de venta, inventarios distribuidos en múltiples sucursales y estructuras de datos multi-esquema, el uso de JavaScript sin tipar introduce riesgos inaceptables de fallas en tiempo de ejecución (`TypeError: cannot read properties of undefined`). TypeScript aporta verificación estática de tipos en tiempo de compilación, interfaces compartidas y autocompletado inteligente en el IDE (Biørn-Hansen et al., 2020). Su capacidad para compartir contratos DTOs entre cliente y servidor elimina inconsistencias en las APIs REST.

#### Node.js 20 LTS (OpenJS Foundation)
- **Rol en el Sistema:** Entorno de ejecución en servidor (*runtime*) para el backend NestJS y la infraestructura de compilación frontend.
- **Justificación y Razones de Elección:**  
  Node.js 20 LTS se fundamenta en el motor Google V8 y la biblioteca `libuv`, implementando un modelo de Entrada/Salida (I/O) no bloqueante dirigido por eventos (*Event Loop*). Esta arquitectura resulta idónea para sistemas SaaS de alta concurrencia de lecturas y escrituras I/O hacia bases de datos y servicios en red, ofreciendo una huella de memoria significativamente menor frente a servidores multi-hilo clásicos basados en bloqueo por hilo (Fowler, 2002).

#### Python 3.11 (Python Software Foundation)
- **Rol en el Sistema:** Lenguaje especializado para el microservicio de analítica avanzada, procesamiento de imágenes para realidad aumentada y orquestación de Inteligencia Artificial Generativa.
- **Justificación y Razones de Elección:**  
  Python es el referente estándar en ciencia de datos, aprendizaje automático y procesamiento de lenguaje natural. La versión 3.11 incorporó el proyecto *Faster CPython*, reduciendo la latencia de ejecución entre un 10% y 60% respecto a versiones previas. Su selección obedece a la madurez de su ecosistema para manipulación matemática de matrices de deformación textil, análisis estadístico y conectividad asíncrona con modelos de lenguaje masivo (LLMs).

### 3.3.1.3. Capa de Presentación Web y Almacenamiento Local Offline (Boundary Objects)

#### React 19 / 18 (Meta Platforms, Inc.) & React DOM
- **Rol en el Sistema:** Biblioteca principal para la construcción declarativa de las interfaces de usuario del panel administrativo, e-commerce web y punto de venta (POS).
- **Justificación y Razones de Elección:**  
  React desacopla la definición visual de los componentes del estado subyacente mediante el algoritmo de reconciliación del DOM Virtual. En el contexto de un Punto de Venta en mostrador (CU-15), donde el cajero escanea productos velozmente requiriendo recálculo instantáneo de subtotales, IVA y cambio en efectivo, React garantiza actualizaciones a 60 FPS sin renderizados innecesarios.

#### Vite 6 (Evan You & Comunidad de Código Abierto)
- **Rol en el Sistema:** Entorno de desarrollo ultrarrápido y empaquetador para producción.
- **Justificación y Razones de Elección:**  
  Frente a empaquetadores tradicionales como Webpack que procesan toda la aplicación antes de iniciar, Vite aprovecha los módulos nativos de JavaScript en el navegador (*Native ES Modules*) y compila dependencias previas mediante `esbuild` (escrito en Go), permitiendo arranques en milisegundos y Reemplazo de Módulos en Caliente (*HMR*) instantáneo. Para producción, compila mediante Rollup aplicando *tree-shaking* agresivo para minimizar el peso de los paquetes descargados por el cliente.

#### Tailwind CSS 3.4, CVA, clsx & Tailwind-Merge
- **Rol en el Sistema:** Sistema de diseño atómico y utilidades de estilización para interfaces web.
- **Justificación y Razones de Elección:**  
  Tailwind CSS procesa estilos bajo demanda mediante su motor JIT (*Just-In-Time*), purgando clases no utilizadas y generando hojas de estilo comprimidas inferiores a 20 KB en producción. `Class-Variance-Authority` (CVA), `clsx` y `tailwind-merge` proporcionan utilidades para crear componentes reutilizables con variantes tipadas (siguiendo los patrones de Shadcn UI), resolviendo conflictos de clases CSS y garantizando uniformidad estética sin colisiones de nombres de clase.

#### TanStack React Query v5 (Tanner Linsley)
- **Rol en el Sistema:** Administrador de estado asíncrono, sincronización remota y caché en memoria.
- **Justificación y Razones de Elección:**  
  Gestiona de forma desacoplada el ciclo de vida de los datos remotos del servidor, implementando de forma automática el patrón *Stale-While-Revalidate*, reintentos exponenciales automáticos tras la reconexión de red y deduplicación de consultas HTTP. Facilita que al restablecer la conectividad tras una venta offline, el inventario del POS se revalide transparentemente sin necesidad de recargar la aplicación.

#### Zustand 5 (Paul Henschel & Daishi Kato)
- **Rol en el Sistema:** Gestor de estado global síncrono del lado del cliente para el carrito de compras, la sesión del usuario, la sucursal activa y el selector de tenant (*Switch-Tenant*, CU-19).
- **Justificación y Razones de Elección:**  
  A diferencia de Redux (que introduce una sobrecarga excesiva de *actions*, *reducers* y *boilerplate*) o React Context (que provoca re-renderizados masivos en árboles profundos de componentes cuando cambia un valor simple), Zustand es una solución minimalista de menos de 1 KB basada en *hooks*. Permite suscribirse únicamente a rebanadas atómicas de estado (`useCartStore(s => s.items)`), maximizando el rendimiento en el punto de venta y en la navegación móvil.

#### React Hook Form 7 & Zod 4
- **Rol en el Sistema:** Motor de captura, validación de esquemas y gestión de formularios de alta densidad de datos.
- **Justificación y Razones de Elección:**  
  React Hook Form utiliza componentes no controlados basados en referencias nativas del DOM, evitando re-renderizados de la pantalla con cada pulsación del teclado en formularios extensos como el alta de sucursales o la creación de tiendas (CU-17). La integración con Zod a través de `@hookform/resolvers` garantiza que las reglas de validación se declaren en esquemas tipificados con inferencia estática, impidiendo el envío de datos no conformes hacia el backend.

#### Dexie.js v4 sobre IndexedDB (David Fahlander)
- **Rol en el Sistema:** Motor de persistencia transaccional en el navegador para la arquitectura Offline-First del POS (CU-15 y CU-16).
- **Justificación y Razones de Elección:**  
  *LocalStorage* es síncrono, bloquea el hilo de renderizado y posee un límite estricto de 5 MB. Dexie.js proporciona una capa ergonómica basada en promesas sobre la API nativa de *IndexedDB*, ofreciendo soporte completo para transacciones ACID reales, índices secundarios y consultas avanzadas. En FashionStore almacena localmente el catálogo de productos y la tabla `syncQueue` (Buzón de salida o *Outbox Pattern*), garantizando que las ventas offline persistan de forma segura incluso ante reinicios accidentales del equipo.

#### Vite Plugin PWA & Workbox Window (Google Chrome Team)
- **Rol en el Sistema:** Transformación de la aplicación web en una *Progressive Web App* (PWA) instalable y resiliente sin conexión.
- **Justificación y Razones de Elección:**  
  Genera automáticamente el archivo manifiesto de la aplicación (`manifest.webmanifest`) y configura *Service Workers* gobernados por Workbox. Permite el pre-almacenamiento en caché (*pre-caching*) de todos los activos estáticos (HTML, JS, CSS, fuentes e iconografía), asegurando que el personal de caja pueda abrir y operar el POS incluso si la computadora carece de conexión a Internet al momento de iniciar la jornada comercial.

#### Stripe SDK (Stripe JS & React Stripe JS)
- **Rol en el Sistema:** Pasarela de pago en línea segura para el cobro de suscripciones SaaS (CU-18) y transacciones de e-commerce.
- **Justificación y Razones de Elección:**  
  Stripe Elements renderiza campos de tarjeta dentro de marcos seguros (*iFrames*) alojados directamente en la infraestructura certificada PCI-DSS Nivel 1 de Stripe. Esto garantiza que la información confidencial de las tarjetas de crédito jamás toque la memoria ni los servidores de FashionStore, minimizando el alcance del cumplimiento normativo de seguridad financiera (*PCI Scope*).

#### Axios & OpenAPI-TypeScript
- **Rol en el Sistema:** Cliente de transporte HTTP con interceptores y generación automatizada de contratos de tipos.
- **Justificación y Razones de Elección:**  
  Axios permite interceptar peticiones de manera centralizada para inyectar cabeceras de autorización (`Authorization: Bearer <token>`) y cabeceras de inquilino (`X-Tenant-Slug`), así como interceptar respuestas HTTP 401 para solicitar la rotación de tokens mediante el `RefreshToken`. `OpenAPI-TypeScript` analiza la especificación Swagger generada por el backend NestJS y genera automáticamente definiciones de tipos TypeScript para el cliente frontend, asegurando sincronización continua de contratos sin esfuerzo manual.

#### Recharts & Lucide React
- **Rol en el Sistema:** Visualización gráfica declarativa de analítica empresarial (CU-20) e iconografía vectorizada SVG.
- **Justificación y Razones de Elección:**  
  Recharts se apoya en elementos vectoriales SVG y componentes reutilizables de React para renderizar diagramas de barras, líneas y sectores con adaptación automática a resoluciones de pantalla y efectos de inspección táctil. Lucide React ofrece una colección de más de mil íconos limpios con soporte nativo de *tree-shaking*, garantizando que únicamente se compilen en el artefacto final los glifos utilizados.

#### React Router DOM 7
- **Rol en el Sistema:** Enrutamiento declarativo del lado del cliente en la aplicación web monomando (SPA).
- **Justificación y Razones de Elección:**  
  Administra la navegación jerárquica, layouts compartidos, rutas protegidas por roles (RBAC) y extracción de parámetros de URL (slug de la tienda, identificador de orden), sincronizando la barra de direcciones del navegador sin recargar la página.

Las bibliotecas de *Worklets* ejecutan funciones de visión artificial en un hilo en segundo plano C++. `Nitro Modules` y `Nitro Image` permiten transferir los fotogramas capturados por la cámara hacia el motor de Skia compartiendo punteros de memoria directos sin copiar los bytes de la imagen, eliminando la recolección de basura (*Garbage Collection*) repetitiva y evitando caídas de fotogramas.

### 3.3.1.5. Capa de Negocio y Servicios de Control (Control Objects - Backend NestJS)

#### NestJS Framework 12 (Kamil Myśliwiec)
- **Rol en el Sistema:** Marco de trabajo arquitectónico para la API REST principal, lógica transaccional y servicios de dominio.
- **Justificación y Razones de Elección:**  
  Ofrece una arquitectura robusta inspirada en Angular y principios de *Clean Architecture*, basada en Inversión de Control (IoC) e Inyección de Dependencias (DI). Esto permite mapear de manera transparente los *Control Objects* del proceso ICONIX a servicios especializados desacoplados de la infraestructura. Facilita la modularidad del sistema mediante módulos temáticos (`AuthModule`, `CatalogModule`, `InventoryModule`, `OrdersModule`, `SaasModule`, `PaymentsModule`).

#### Argon2id (`argon2`) & Passport JWT
- **Rol en el Sistema:** Mecanismos de seguridad criptográfica para almacenamiento de contraseñas y emisión de credenciales de acceso.
- **Justificación y Razones de Elección:**  
  Argon2id es el algoritmo recomendado internacionalmente por OWASP y ganador de la *Password Hashing Competition*, por su resistencia física contra ataques paralelos masivos mediante GPUs o ASICs. Passport JWT gestiona el ciclo de vida de tokens de autenticación sin estado (*stateless*), combinados con tokens de refresco revocables almacenados en base de datos para mitigar el riesgo de robo de credenciales.

#### Class-Validator & Class-Transformer
- **Rol en el Sistema:** Validación y sanitización automática de datos entrantes a nivel de DTO (Data Transfer Object).
- **Justificación y Razones de Elección:**  
  Interceptan todas las peticiones entrantes mediante decoradores declarativos (`@IsString()`, `@IsUUID()`, `@Min()`, `@IsEnum()`). Si el payload no coincide con las restricciones estrictas del contrato de la API, el validador detiene la ejecución inmediatamente retornando un error HTTP 400 (*Bad Request*), blindando los *Control Objects* contra inyecciones de parámetros y manipulación masiva de propiedades no autorizadas.

#### Stripe Node SDK (Stripe Inc.)
- **Rol en el Sistema:** Integración de la pasarela de pagos para el cobro automatizado de planes de suscripción SaaS (CU-18) y verificación de webhooks.
- **Justificación y Razones de Elección:**  
  Permite la gestión desatendida del ciclo de vida de facturación (altas de clientes, creación de suscripciones periódicas mensuales/anuales, cobros recurrentes y reintentos automáticos tras fallas de tarjeta). Los webhooks de Stripe se procesan mediante firmas criptográficas de tiempo (*HMAC-SHA256*) y claves de idempotencia, asegurando que un mismo cobro no se compute por duplicado en el libro mayor contable.

#### @nestjs/schedule (Cron Jobs)
- **Rol en el Sistema:** Planificador de tareas en segundo plano periódicas para el mantenimiento automatizado de estados de negocio.
- **Justificación y Razones de Elección:**  
  Ejecuta rutinas periódicas desatendidas (como la liberación de stock bloqueado por reservas expiradas que superan el tiempo de gracia, o la verificación nocturna del estado de activación de inquilinos SaaS con cuotas impagas) sin requerir demonios externos o dependencias complejas de orquestación.

#### @nestjs/swagger (Documentación OpenAPI 3)
- **Rol en el Sistema:** Generación automatizada de la especificación técnica de la API y panel interactivo Swagger UI en `/api/docs`.
- **Justificación y Razones de Elección:**

### 3.3.1.6. Capa de Persistencia y Aislamiento Multitenant (Entity Objects)

#### PostgreSQL 16 (PostgreSQL Global Development Group)
- **Rol en el Sistema:** Sistema Gestor de Bases de Datos Relacional (RDBMS) central para la persistencia transaccional de todos los datos maestros, operacionales, contables y de auditoría de la plataforma.
- **Justificación y Razones de Elección:**  
  PostgreSQL es ampliamente reconocido como el motor de base de datos relacional de código abierto más robusto, dotado de cumplimiento estricto de las propiedades ACID y una arquitectura de control de concurrencia multiversión (*MVCC*) de alta eficiencia (Kleppmann, 2017).  
  Para implementar el modelo multitenant de FashionStore, se descartaron tanto la estrategia de base de datos por inquilino (*Database-per-tenant*, por su excesivo consumo de memoria en conexiones inactivas y complejidad operativa en migraciones DDL masivas) como la estrategia de columna compartida (*Shared Database with tenant_id column*, por el riesgo inaceptable de filtración cruzada de datos ante una omisión involuntaria de la cláusula `WHERE tenant_id = ...` en el código fuente).  
  La solución implementada fue el **aislamiento por esquemas PostgreSQL (`schema-per-tenant`)**:
  - El esquema central `public` alberga las tablas de administración global del SaaS (`tenants`, `tenant_memberships`, `users`, planes de suscripción y límites).
  - Cada empresa cliente dispone de su propio espacio de nombres lógico aislado (`tenant_<slug>`), con sus propias tablas independientes de órdenes, inventarios, movimientos de kardex y transacciones de caja.
  - El motor PostgreSQL resuelve el aislamiento físico y de permisos mediante la variable de sesión `search_path`, garantizando que ninguna consulta ejecutada dentro del contexto de una tienda pueda acceder jamás a las filas o tablas de otra tienda vecina. Adicionalmente, el soporte nativo de tipos `JSONB` indexados mediante índices invertidos generalizados (*GIN*) permite a cada inquilino almacenar atributos dinámicos y variantes de ropa sin alterar el esquema relacional rígido.

#### Prisma ORM 6 (Prisma Data, Inc.)
- **Rol en el Sistema:** Mapeador objeto-relacional (ORM) de última generación para Node.js y TypeScript.
- **Justificación y Razones de Elección:**  
  Prisma introduce un enfoque declarativo basado en un archivo de esquema central (`schema.prisma`), a partir del cual el motor genera automáticamente un cliente de TypeScript fuertemente tipado (*Prisma Client*). Cada consulta (`prisma.order.create(...)`) garantiza en tiempo de compilación que todos los campos requeridos estén presentes y posean el tipo correcto.  
  Para el aprovisionamiento de nuevos inquilinos (CU-17), Prisma permite ejecutar comandos DDL directos en transacciones atómicas (`CREATE SCHEMA tenant_<slug>`), clonando la estructura de tablas maestras de forma automatizada y sin intervención manual de administradores de bases de datos.

### 3.3.1.7. Microservicio de Analítica e Inteligencia Artificial Generativa (Control Objects - AI Service)

El procesamiento de consultas gerenciales en lenguaje natural y la generación segura de reportes ejecutivos (CU-20), junto con los módulos de asistencia conversacional, recomendaciones y ajuste virtual, se desacoplaron en un microservicio Python estructurado:

```
                  ESTRUCTURA MODULAR DEL MICROSERVICIO DE IA (FastAPI)
 
   app/
   ├── core/                    # Configuración (.env), Seguridad (Argon2/JWT) y Excepciones
   ├── database/                # Conexión asíncrona SQLAlchemy 2.0, Sesión y Semillero
   └── modules/
       ├── assistant/           # Asistente Conversacional Inteligente para Clientes y Staff
       ├── generative_reports/  # Motor ReportIQ (Zero SQL Injection) para Reportes con IA
       ├── recommendations/     # Modelo de Recomendación de Prendas y Filtrado Colaborativo
       └── virtual_fitting/     # Generación y Deformación de Texturas WebP para Vestidor AR
```

#### FastAPI (Sebastián Ramírez) & Uvicorn (ASGI Server)
- **Rol en el Sistema:** Microframework web asíncrono y servidor de alto rendimiento para la API REST del microservicio de inteligencia artificial.
- **Justificación y Razones de Elección:**  
  FastAPI aprovecha de forma nativa la sintaxis `async/await` de Python para manejar conexiones concurrentes sin bloquear el hilo de ejecución principal durante las llamadas de inferencia a modelos de lenguaje o durante el procesamiento de imágenes para realidad aumentada. Genera automáticamente especificaciones OpenAPI 3.1 interactivas.

#### Pydantic v2 (Pydantic Services Inc.) & Pydantic-Settings
- **Rol en el Sistema:** Motor de tipado, serialización y validación estricta de esquemas de datos del microservicio de IA.
- **Justificación y Razones de Elección:**  
  El núcleo de validación de Pydantic v2 fue reescrito enteramente en el lenguaje **Rust** (*pydantic-core*), incrementando la velocidad de análisis y validación entre 5 y 20 veces respecto a su versión anterior. En el flujo del microservicio de reportes, valida que las respuestas del LLM cumplan con la estructura de datos tipificada requerida (métricas, filtros y dimensiones), descartando cualquier intento de inyección de código.

#### SQLAlchemy 2.0, Psycopg 3 & Alembic
- **Rol en el Sistema:** Capa de acceso a datos asíncrona y gestor de migraciones para el microservicio de analítica.
- **Justificación y Razones de Elección:**  
  SQLAlchemy 2.0 unifica los patrones *Core* y *ORM* con soporte nativo para `asyncio`, tipado estático completo y construcciones seguras de consultas parametrizadas. `Psycopg 3` es el adaptador nativo moderno de PostgreSQL para Python, soportando el protocolo binario completo del motor y *connection pooling* asíncrono. `Alembic` administra el historial de migraciones de la base de datos de forma reproducible.

#### Patrón Arquitectónico Zero SQL Injection (ReportIQ) & LLM APIs (HTTPX)
- **Rol en el Sistema:** Estrategia arquitectónica de generación de reportes mediante Inteligencia Artificial sin exposición de la base de datos a sentencias SQL arbitrarias.
- **Justificación y Razones de Elección:**  
  El enfoque habitual de *Text-to-SQL* (pedirle a una IA que escriba sentencias SQL directas) es altamente vulnerable a ataques de *Prompt Injection* y alucinaciones destructivas (`DROP SCHEMA`, lecturas cruzadas entre inquilinos).  
  Bajo el patrón **ReportIQ**:
  1. El modelo de lenguaje (Google Gemini API u Ollama local para despliegues privados) no tiene acceso directo a la sintaxis SQL ni a las tablas de la base de datos.
  2. El modelo traduce el lenguaje natural únicamente a un objeto JSON estructurado validado por Pydantic que especifica tres elementos: la métrica solicitada (por ejemplo, `TOTAL_VENTAS`), el rango de fechas (`LAST_30_DAYS`) y la dimensión de agrupación (`BY_BRANCH` o `BY_CATEGORY`).
  3. El backend toma ese objeto JSON estructurado e invoca una consulta SQL parametrizada y precompilada internamente, inyectando de forma forzada el esquema del inquilino autenticado (`tenant_<slug>`). De este modo, es matemáticamente imposible que una consulta de IA vulnere el aislamiento multitenant o ejecute código no autorizado. La comunicación asíncrona de alta velocidad con las APIs de los modelos de lenguaje se realiza mediante `HTTPX`.

#### Pwdlib [Argon2] & PyJWT
- **Rol en el Sistema:** Verificación unificada de credenciales criptográficas y decodificación de tokens de autenticación en Python.
- **Justificación y Razones de Elección:**  
  Garantiza que el microservicio de Python valide exactamente los mismos hashes Argon2id y los mismos tokens criptográficos JWT emitidos por el backend principal NestJS, manteniendo un esquema de autenticación centralizado y coherente sin dispersión de políticas de seguridad.

#### Pillow 10 & Boto3 (Amazon Web Services)
- **Rol en el Sistema:** Procesamiento y optimización de texturas textiles con canal alfa y almacenamiento de objetos compatible con S3.
- **Justificación y Razones de Elección:**  
  Las imágenes de prendas destinadas al vestidor virtual se procesan por lotes mediante Pillow para eliminar fondos, ajustar dimensiones de relación de aspecto y convertirlas a formato WebP, logrando una reducción de tamaño del 70% comparado con PNG tradicional. `Boto3` proporciona la interfaz cliente estándar para interactuar con sistemas de almacenamiento de objetos compatibles con la API S3 (como AWS S3, Cloudflare R2 o instancias locales de MinIO), asegurando que el almacenamiento multimedia permanezca completamente desacoplado de la base de datos transaccional.

### 3.3.1.8. Herramientas de Soporte, Calidad de Software, DevOps y Control de Versiones

#### Git 2.x & GitHub
- **Rol en el Sistema:** Sistema de control de versiones distribuido y plataforma de alojamiento del repositorio y flujos de integración continua (*GitHub Actions*).
- **Justificación y Razones de Elección:**  
  Permite el seguimiento atómico de los cambios en el código fuente, la auditoría histórica de modificaciones y la colaboración basada en ramas bajo el modelo de *Trunk-Based Development* con ramas protegidas para producción (`main` y `develop`), requiriendo revisiones de código cruzadas (*Pull Requests*) y ejecución exitosa de pruebas automatizadas antes de cualquier fusión.

#### PNPM Workspaces (Performant npm)
- **Rol en el Sistema:** Gestor de paquetes y orquestador del monorepo (`c:\Parcial-si2`).
- **Justificación y Razones de Elección:**  
  A diferencia de npm y Yarn v1, que duplican de forma redundante gigabytes de módulos en cada subdirectorio del proyecto dentro de carpetas `node_modules` pesadas y anidadas, PNPM utiliza un almacén de paquetes direccionable por contenido (*content-addressable storage*) en el disco local y enlaces duros (*hard links*). Esto ahorra hasta un 65% de espacio en disco, acelera los tiempos de instalación en un factor de 3x y previene el acceso indebido a dependencias fantasma no declaradas mediante árboles de dependencias estrictos no planos.

#### Docker & Docker Compose v2 (Docker Inc.)
- **Rol en el Sistema:** Plataforma de contenerización para el empaquetado reproducible de servicios, bases de datos auxiliares y dependencias de infraestructura.
- **Justificación y Razones de Elección:**  
  Elimina el problema de discrepancias entre entornos al encapsular las versiones exactas de PostgreSQL 16, Redis 7, el microservicio de FastAPI y el backend de NestJS dentro de contenedores ligeros aislados a nivel de kernel del sistema operativo. Esto garantiza paridad estricta entre los entornos de desarrollo local de los ingenieros de software, los servidores de pruebas de integración y los clústeres de despliegue en la nube.

#### Jest, Supertest, Vitest & Pytest (Testing Suites)
- **Rol en el Sistema:** Marcos de trabajo para la ejecución de pruebas unitarias, pruebas de integración de endpoints HTTP y pruebas de componentes de interfaz de usuario.
- **Justificación y Razones de Elección:**  
  En consonancia con la fase de pruebas unitarias del proceso ICONIX (Rosenberg & Stephens, 2007), donde cada controlador y servicio debe validar sus casos de prueba positivos y de borde antes del cierre del caso de uso, Jest y Supertest permiten simular peticiones HTTP completas contra los controladores de NestJS verificando la persistencia real en la base de datos multitenant; Vitest proporciona ejecución ultrarrápida de pruebas unitarias en el cliente web reutilizando la configuración de Vite; y Pytest ejecuta las baterías de pruebas sobre los servicios de inferencia de IA.

#### Oxlint, ESLint & Prettier
- **Rol en el Sistema:** Herramientas de análisis estático de código (*linting*) y formateo estandarizado automático.
- **Justificación y Razones de Elección:**  
  Oxlint (desarrollado en Rust) ejecuta análisis estático a velocidades hasta 50 veces superiores a las herramientas clásicas de JavaScript, detectando errores de sintaxis, variables no utilizadas y patrones defectuosos en fracciones de segundo durante el guardado de archivos. ESLint y Prettier complementan la cadena aplicando de forma unificada las reglas de estilo de código en todo el equipo, eliminando debates de formato en revisiones de código y asegurando que la base de código mantenga una legibilidad óptima a lo largo del tiempo.
